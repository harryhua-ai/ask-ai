## 1. 一句话定位

ask-ai 是一个 **RAG 知识助手中台服务**——向上提供多个对接入口(Widget / 消息渠道 / MCP / HEADLESS API),向下可插拔接入各种数据源与 LLM 供应商,中间以统一管线完成检索增强问答,并配套管理后台、可观测与业务情报能力;**CamThink 是第一个用户/实例**。

## 2. 三层产品架构

| 层 | 角色 | 现状 |
|---|---|---|
| **入口层**(前台对接) | 渠道适配器:Widget / Discord / WhatsApp / MCP Server / 第三方系统 HEADLESS 调用 | 仅 Widget(官方旗舰前台);`POST /api/ask` 统一 HTTP+SSE 协议上已可被任意系统调用,但无集成方认证(API key)、配额按 IP 限流、预算为全局熔断——HEADLESS 半开放 |
| **中台层**(产品本体) | 统一 API + RAG 管线(意图/检索/重排/拒答/生成)+ 配置中心 + 管理后台 + 可观测分析 | 已全部实现;`channel` 字段贯穿数据模型,加入口"只写适配器、中台零改"的架构承诺成立 |
| **资源层**(可插拔后端) | 数据源连接器、LLM Provider、embedder 档位 | 双注册表插件化已就绪;已实现 4 类连接器 + openai_compatible LLM,扩类型不改管线 |

> 该定位是 founding spec §3"统一 HTTP API + 渠道适配器"架构的**升格**:多渠道从 Phase 4 远期项变为产品核心定位的入口层;Widget 从"产品全部"变为"第一个/旗舰前台"。

## 3. 双层身份

| 层 | 身份 | 含义 |
|---|---|---|
| 产品层 | 通用中台标准件 | ask-ai 本体:可复用、可配置、可交付给第二个组织的 RAG 中台 |
| 实例层 | CamThink 实例 | 第一个部署:语料是 CamThink 产品线,业务参数(意图/品牌/分析域)是 CamThink 的 |

**历史背景**(立项决策):Kapa.ai SaaS 数据出域,与数据自主冲突 → 自建;Hermes 改造四重错位 → 排除。"数据自主"从 CamThink 的要求升级为**标准件的核心卖点**。

**最终形态**:标准件多实例——每个租户/实例:自有语料接入、自有品牌入口、自有意图体系与业务参数、自有 LLM 配置,数据全部留在自己基础设施;上游产品统一演进。

**产品边界演进**:Phase 1 明确"只回答问题 + 推荐页面,不收集线索、不转人工、不做账户/订单查询"。边界已部分松动——客户信息模型(留资轻量表单)规划中,是产品从纯问答向商业闭环的第一步,属规划未实施。

## 4. 战略决策锚点(全文见 PRODUCT_ROADMAP 决策记录)

- **D-1 产品形态**:私有部署商业授权(单实例交付,非 SaaS 多租户);配套 licensing + onboarding + 版本化迁移
- **D-2 目标客户**:科技公司为主(代码索引/开发者支持为核心卖点)
- **D-3 入口层路线**:标准 web 插件(widget 一行脚本嵌入)优先;MCP/Discord/WhatsApp/HEADLESS 预留
- **D-5 北极星**:分层双指标(见 §6)
- **D-4 集成方模型**:暂不定,等第一个系统级对接需求

## 5. 用户与价值

| 用户群 | 触点 | 核心价值 |
|---|---|---|
| **标准件客户**(未来实例部署者) | 部署物 + onboarding | 拿到即用的知识助手:接语料、配品牌、上线问答 |
| **潜在客户**(商务) | Widget,匿名 | 价格/采购/渠道咨询(commercial) |
| **产品选型者** | Widget,匿名 | 功能/参数/规格/选型/方案(product) |
| **开发者/集成方** | Widget,匿名 | 故障排查/集成/代码/调试(support) |
| **业务/管理者** | Admin 业务概览 | 销售线索、场景应用、产品需求三大业务信号 |
| **运营** | Admin 对话审查 | 单条对话质量诊断(全链路 trace) |
| **技术** | Admin 技术洞察/数据源/模型配置 | 系统健康、知识缺口、索引与 LLM 配置 |

(各群当前可用状态见 PRODUCT_STATE。)

## 6. 北极星指标(D-5,分层双指标)

| 层 | 北极星 | 价值故事 |
|---|---|---|
| 产品层(标准件,面向科技公司客户) | **自助解决率**(技术问题被助手直接答掉、未占人工支持的比率) | "省支持人力"——可复用、与客户定位咬合 |
| 实例层(CamThink) | **有效线索数**(commercial 且非 off_topic 的真实咨询条数) | "发现潜在客户"——CamThink 特有(商城 + 销售团队) |

两线近期排序由实例数据裁决:commercial 咨询占比高 → 优先商业闭环;占比低 → 优先质量地基。

## 7. 产品原则与不变量(红线,跨阶段不可破坏)

1. **拒答优先于编造**:无依据不回答(双层拒答:off_topic 检索前 + rerank 阈值检索后);拒答入统计供缺口分析
2. **数据自主**:全部语料/向量/对话数据在自有基础设施,不训练公开模型
3. **匿名与隐私**:不收集身份信息,PII 入库前脱敏,日志保留期 90 天(D-8)
4. **安全铁律**:secret 不进 LLM 上下文;LLM 输出与知识库 chunk 均不视为可信内容;未来工具调用须最小权限 + 危险动作人工确认
5. **运营红线**(工程):`--reindex` 删全量 collection 非单源;测试必设 `TEST_DATABASE_URL`;生产纯镜像禁源码挂载
