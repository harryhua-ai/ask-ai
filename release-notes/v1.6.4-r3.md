# v1.6.4-r3 — Answer Evidence and Operational Safety

## Version

v1.6.4-r3

## Summary

This release source records the changes between the `v1.6.4-r2` tag commit
`8052b358b68c9dad72c10c4359e094b02bd16374` and accepted `main` at
`7b680ac1b3f66846440902eaaa89dd1a8bf0fdae`. GitHub's compare reports 66
commits across 101 files. The changes improve answer evidence selection,
administrative auditability, and release and data-cleanup safeguards. Source
integration and CI results do not by themselves establish production behavior.

## User-visible changes

- Solution and Case answers now require first-party website identity and a
  matching full `/solutions/` URL path; a matching path on an unrelated source
  is not enough. Final selection preserves required Solution/Case evidence
  without crowding out qualified Store price evidence. Multi-product purchase
  answers also retain eligible Store evidence per requested product.
  ([PR #156](https://github.com/harryhua-ai/ask-ai/pull/156), merge
  `2ed60617e6dff29933268f8d64bb8dc9000af340`; [PR #157](https://github.com/harryhua-ai/ask-ai/pull/157),
  merge `02fcb82742a60ea7b75212feb4ba27588f97087b`)
- Authorized uploaded knowledge can support Widget answers without displaying
  an internal filename, path, or fabricated numbered citation when it has no
  visitor-accessible URL. Source eligibility remains governed by explicit
  channel visibility; hiding a citation does not grant access.
  ([PR #132](https://github.com/harryhua-ai/ask-ai/pull/132),
  [PR #150](https://github.com/harryhua-ai/ask-ai/pull/150), merge
  `4914997ba80d3a5dc84f38096405fdd64200a38f`)
- Widget page context now derives product identity from recognized official
  pages. Hardware-revision evidence is gated by revision, and unresolved
  accessory context does not produce a confident answer.
  ([PR #134](https://github.com/harryhua-ai/ask-ai/pull/134),
  [PR #126](https://github.com/harryhua-ai/ask-ai/pull/126), commit
  `c68cf699c208a809e065ab163ec44ec045ebcc9f`)
- Broadly answerable questions are less likely to be stopped by an unnecessary
  clarification prompt; product-selection questions still require enough
  context to identify the requested product.
  ([PR #133](https://github.com/harryhua-ai/ask-ai/pull/133))

## Admin / operator changes

- The daily conversation chart renders proportional bars and groups records by
  Asia/Shanghai business days.
  ([PR #129](https://github.com/harryhua-ai/ask-ai/pull/129))
- Lead contact detection filters technical noise such as log timestamps,
  IPv4 addresses, and version strings. Admins can audit an invalid-contact action;
  the action preserves the original contact fields and records the reason and
  operator. Qualification provenance is retained for review.
  ([PR #128](https://github.com/harryhua-ai/ask-ai/pull/128),
  [PR #131](https://github.com/harryhua-ai/ask-ai/pull/131),
  [PR #135](https://github.com/harryhua-ai/ask-ai/pull/135),
  [PR #140](https://github.com/harryhua-ai/ask-ai/pull/140), merge
  `34f48cfd4b6294bbb2da6b9efa599091fba294d6`)
- Scope-external orphan rows have an explicit audited retirement path that
  requires server-side proof of current, identity-matched physical absence.
  This adds an operator control; it does not report that production rows were
  retired.
  ([PR #137](https://github.com/harryhua-ai/ask-ai/pull/137), merge
  `cf7af4d61e4bc811779994849d16a54442139108`)

## Compatibility / migration notes

The deployment migration manifest adds two additive `sales_leads` migrations:

1. `scripts/migrate_add_sales_lead_contact_void.py` adds the contact-void
   audit fields (`contact_voided`, `contact_voided_at`, `contact_voided_by`,
   and `contact_voided_reason`). It does not delete or rewrite the original
   contact values.
2. `scripts/migrate_add_sales_lead_qualification_provenance.py` adds
   `qualification_provenance`; it does not backfill historical rows, whose
   provenance remains `NULL` when it cannot be established.

Both scripts are registered in `deploy/prod/migrations.json`. Registration
does not establish that either migration has run in production.

`deploy/prod/compatibility.json` continues to declare
`previous_compatible=false` and
`remediation_gate=upload-source-acl-verified-issue-121`. This remains an
independent prerequisite for deployment and recovery. Closing #121 as
`CLOSED / NOT PLANNED` does not satisfy the source-ACL or rollback gate; this
release note does not create a remediation acknowledgement or change that
declaration.

## Known limitations

- The latest recorded production outcomes for #28, #31, and #106 remain FAIL;
  acceptance of answers from this version is UNKNOWN pending authorized
  production validation. A successful CI run is not answer acceptance.
- GeoIP2 remains default-off, and #114 production AC6 has not been verified.
- #164's preflight is read-only. Although #168's GC safety fix is merged,
  production GC apply remains prohibited; no production PostgreSQL or
  Weaviate deletion is asserted here.
- This source and its main-branch CI do not establish a tag-specific release
  image, a production deployment, or completion of the independent
  `compatibility.json` gate.
