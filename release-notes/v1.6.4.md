# v1.6.4 — Production Correctness + Release-Path Readiness（Commerce Freshness · Solution Evidence Recall · Test-DSN Release Gate）

## Version

v1.6.4

## Summary

This release closes the production-acceptance blockers discovered during the
authorized v1.6.3-r9 acceptance wave (#48/#28/#31), plus the release-engineering
defect that forced a break-glass deployment in that wave.

## User-visible changes

- Solution / recommendation answers can now surface the official first-party
  Solution page and matching first-party Case-study evidence in both Chinese
  and English. Previously these authoritative pages could be absent from the
  answer context entirely while unrelated internal support tickets occupied
  the case-evidence role.
- Evidence-role coverage for equivalent EN/ZH queries no longer diverges by
  evidence class (official Solution / first-party Case / Product-Wiki roles).

## Admin / operator changes

- WooCommerce commerce metadata (stock, price, sale state, purchasability)
  now converges to Store truth through the normal canonical sync:
  - content-bearing commerce changes (stock/price/sale) propagate through
    content re-ingest with full row-truth sync on activation;
  - metadata-only commerce changes (purchasable / permalink / timestamps)
    propagate through the zero-re-embed metadata path with truthful
    `commerce_synced_at`, retry-safe fail-closed serving updates, and
    historical mirror-drift reconciliation on the empty-incremental pass —
    strictly bounded to UNCHANGED-class documents (no re-embed, no version
    or generation churn, idempotent on re-sync);
  - sync delta accounting gains an additive `mirror_reconciled_count`
    document-unit fact.
- No manual SQL, vector mutation, or reindex is required for commerce
  freshness.

## Engineering / release changes

- The #102 lock-safety PostgreSQL tests now honor the repository-canonical
  `TEST_DATABASE_URL` contract: the CI-provided test database is authoritative,
  settings fallback is restricted to non-prod shapes, and prod-mode execution
  without an explicit test DSN fails closed instead of silently pointing
  `init_db`/DDL/LOCK probes at the settings (production-shape) database.
  This restores the primary tag/release artifact path (CI run evidence:
  the lock-safety file previously failed 5/5 in release CI for harness
  reasons).
- #102 lock ordering, lock_timeout, steady-state no-DDL and bounded-progress
  assertions are unchanged in meaning and pass on the corrected harness.

## Compatibility / migration notes

- No new database migrations in this release (ledger unchanged at 14 entries).
- No intentional breaking API change.
- Retrieval behavior changes are bounded to solution/recommendation-intent
  queries with Solution/Case evidence slots; support, factual and commercial
  queries keep their existing recall contract. Product isolation, fail-closed
  retrieval, citation numbering and citation integrity semantics are intact.

## Known limitations

- The expected NeoMind OCR model-use-case authority document (NE101 Camera AI
  Vision / paddle-ocr pipeline) does not exist in the configured upstream
  sources (verified read-only against the wiki-documents and NeoMind
  repositories). It is recorded as an external content gap; the system does
  not fabricate it. Adjacent NeoMind developer documentation (128 active
  documents) is already indexed.
